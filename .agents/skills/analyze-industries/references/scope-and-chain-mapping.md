## 1. 范围声明

研究开始先写一段可审计的范围声明：

```text
研究对象：
核心产品/服务：
解决的终端需求：
地理范围：
基准期与预测终点：
采用的交易层级：
纳入：
排除：
相邻市场：
默认分析视角：
```

同一个行业名可能同时指技术、产品、公司集合或终端需求。优先用可交易产品、购买方和用途定义边界。例如“储能”至少可能包括电芯、PCS、系统集成、EPC、运营和辅助服务，不能直接使用一个未经定义的总规模。

## 2. 节点与边的定义

给每个节点稳定 ID，例如：

- `R`：资源与原料。
- `M`：材料与中间品。
- `E`：设备、工具与关键工艺。
- `C`：核心部件。
- `S`：制造、系统与集成。
- `I`：基础设施和使能层。
- `D`：渠道、交付与运营。
- `A`：终端应用。
- `P`：耗材、维修、服务和回收。

节点必须有：

| 字段 | 定义 |
|---|---|
| `node_id` | 稳定编号，版本更新时不随名称轻易变化 |
| 名称 | 使用行业通行名称并列同义词 |
| 输入 | 从上一节点购买或取得的资源 |
| 输出 | 可以独立交易、计价或核算的产品/服务 |
| 卖方 | 典型供应者类别 |
| 买方 | 直接付费客户，不等同最终用户 |
| 计价单位 | 吨、台、GW、席位、交易额、项目等 |
| 地理归属 | 生产地、消费地或收入确认地 |
| 上下游 | 指向相关节点 ID |
| 纳入/排除 | 防止边界漂移 |
| 数据状态 | 已量化、部分、不可得或不适用 |

边记录物料、资金、数据、客户或许可的流动类型。产业链可以是有向无环图，也可以存在回收、数据反馈和平台网络效应；不要为了画图强制改成直线。

## 3. 拆解顺序

### 从终端需求反推

1. 明确最终付费者和使用场景。
2. 拆出交付给终端的系统、产品或服务。
3. 拆出决定性能、成本或供应安全的部件与材料。
4. 拆出制造所需设备、工具、软件、基础设施和认证。
5. 补充渠道、运营、耗材、维护和回收。

### 从交易发票验证

对每个候选节点提问：

- 买方购买的究竟是什么？
- 常用价格单位是什么？
- 能否观察独立收入、出货、产能或合同？
- 主要参与者是否与相邻节点不同？
- 该节点是否有独立利润率、议价权或监管要求？

如果回答大多为否，通常应并入相邻节点。

### 从关键约束补漏

检查是否遗漏：

- 稀缺资源、许可证或标准。
- 关键设备、耗材和软件工具。
- 测试、认证、物流、安装与运维。
- 电力、算力、网络、场地和融资。
- 渠道、平台、经销商或集采方。
- 回收、处置和循环利用。

只在这些要素形成独立交易、成本或瓶颈时设节点。

## 4. 停止规则与颗粒度

默认使用二级环节。满足任一条件时下钻：

- 该子环节贡献显著市场或利润池。
- 国产化率、增长率或竞争结构与母节点明显不同。
- 是供给瓶颈、技术卡点或认证关口。
- 上市公司业务暴露需要更细颗粒度才能判断。
- 用户明确要求该层。

只有同时具备以下多数特征才新建三级节点：

1. 独立产品或服务。
2. 独立买方或采购决策。
3. 独立计价方式。
4. 不同参与者集合。
5. 不同单位经济性或壁垒。

不要把企业内部工序、没有外部交易的功能模块或宣传术语机械变成市场。

## 5. 常见产业结构

### 垂直制造链

`资源 → 材料 → 设备/工艺 → 部件 → 整机/系统 → 渠道/运营 → 终端 → 后市场`

设备通常与材料/部件并列作为使能层，而不是简单处于最上游。

### 项目与基础设施

`核心设备 + 工程设计 + EPC + 融资/许可 → 项目资产 → 运营服务 → 用户`

区分一次性建设市场和存量运营市场。

### 软件与订阅

`基础算力/数据 → 开发工具/中间件 → 产品平台 → 渠道/实施 → 客户`

同时画出部署方式、生态插件、数据供应方和实施服务。

### 双边或多边平台

围绕平台画：

- 供给侧参与者。
- 需求侧参与者。
- 支付、物流、广告、数据和基础设施。
- 平台抽成、补贴和跨边网络效应。

市场规模要区分 GMV、平台净收入、商户收入和服务商收入。

### 资源与商品

`资源储量 → 开采 → 选冶/加工 → 贸易/物流 → 消费行业 → 回收`

资源量、储量、产能、产量、库存和消费不能混用。

## 6. 覆盖门

建立覆盖矩阵：

| 节点ID | 定义 | 全球规模 | 中国规模 | 参与者 | 经济性 | 潜力 | 来源 | 数据状态 |
|---|---|---|---|---|---|---|---|---|

提交前必须满足：

- 所有图中节点都出现在覆盖矩阵。
- 节点定义表、覆盖矩阵与链图的具名节点集合完全一致；箭头说明中不得出现未编号的隐含环节。
- 所有规模表节点都能回到链图。
- 所有主要参与者都标明实际参与节点。
- 每个节点至少有定义、买方、卖方和计价单位。
- 数据不足节点保留并解释补数路径。
- 不适用字段明确标记，不留空白造成“遗忘”假象。

将节点分为：

- **核心节点**：决定行业规模、利润池、瓶颈或投资映射，必须深挖。
- **支持节点**：需要覆盖但可简写。
- **相邻节点**：只用于解释替代、交叉销售或进入风险。

需求锚、系统集成、终端应用、运维和回收即使不计入核心市场规模，只要在链图中具名，也必须编号并在覆盖矩阵中标为“支持/相邻、不计入核心规模”。

## 7. 质量检查

- 产业链是否从实际终端需求开始而不是从公司名单开始？
- 是否区分付费客户与最终用户？
- 是否把设备、软件、服务和基础设施遗漏在制造链之外？
- 是否同时画物量流和价值流需要不同节点？
- 是否把内部工序误当外部市场？
- 是否存在同一节点在多个分支重复计数？
- 全球和中国使用的链图边界是否一致？
- 新技术是否替代原节点、叠加新节点，还是仅改变节点内工艺？
- 每个高潜结论能否回到一个明确节点和交易标的？
